## 一、已修复

### 1. `BookNameMod` 丢失指纹缓存 —— 每秒读盘 + 重复 SHA-256（性能回归）

- **现象**：法语版 `SlotProfile()` 删掉了日语参照实现里的 5 秒 TTL 缓存
  （`_slotProfileAt[4]`），注释改为「每次重新验证以免覆盖槽位后误接管」。
- **代价（本机实测）**：`Scan()` 每秒跑一次 `SelectedManagedBook()` →
  `SlotProfile()` → 重新反序列化 `MyBook.es3`（**1.08 MB**，8.5 ms）
  + `BookProfiles.Match()` 对 8,116 词做归一化/排序/SHA-256（1.1–1.7 ms 热、10.3 ms 冷），
  且 `Match` 每次被调用 2 次（内存词表 + 槽位词表）。
  即**常驻 ~11.5 ms/秒的主线程开销**（冷启动单帧可达 ~28 ms），外加每秒 2.4 万个字符串的 GC 分配。
- **修复**：恢复日语参照实现的 5 秒 TTL 缓存（`mod_book_name/BookNameMod.cs`）。
  恢复后 `FR vs JP` 仅剩 4 处**有意增强**的差异（见下）。
- **验证**：`mod_book_name\build.cmd` BUILD OK + 已部署（`BookNameMod.dll` mtime 01:09:03）。

法语版相对日语参照 **有意保留的 4 处增强**（复查确认均正确，不建议回退）：

| 位置 | 增强 | 为什么对 |
|---|---|---|
| `ForceJpLabels` | 增加 `!isActiveAndEnabled` 判断 | 插件被禁用后 Harmony 仍会调用补丁 |
| `ToCosmeticIfManaged` | 增加 `isActiveAndEnabled` + `_enabled.Value` 判断 | 同上，防禁用后继续改写 UI |
| `Scan` | 由 `_lastJpBook`(bool) 改为比较 `_lastVoiceLabel`(字符串) | 支持日→法、法→日**跨语言**切换时正确还原（bool 版本漏掉这条）；并补了 `OnDisable`/`OnDestroy` 还原 |
| `EnforceSingleWordJp` | 不再点亮「游戏自己关掉、我们没动过」的节点 | 否则切回英语词书会把本该隐藏的图标点亮 |

### 2. `tools/deprecated/isolate_word_audio_fr.py` 从未可用过，且目标目录是错的

- **两个独立缺陷**：
  1. `ROOT = Path(__file__).resolve().parent.parent` —— 脚本在 `tools/deprecated/` 下，
     解析结果是 `D:/French/tools`，于是去找 `tools/output/french_books.json`。
     **该脚本从放入 deprecated 起就没成功跑过一次**（实测直接 `FileNotFoundError`）。
  2. `FR_AUDIO` 指向 `LocalLow/WCP/fr_audio`，而插件实际读
     `LocalLow/WCP/wcp/fr_word_audio`。真跑 `--restore` 会去错误目录找文件 →
     静默报告「移回 0 个」，而 8,116 个文件仍留在正确的私有目录。
- **修复**：`ROOT = TOOLS.parent`；`FR_AUDIO = audio_paths_fr.word_audio_dir()`
  （与生成端、插件端**同一个常量**）；顺带把「已隔离」与「真丢失」分开统计
  （否则每次跑都刷 8,116 条"缺失"噪声）。
- **验证**：实跑输出 `已移到 fr_word_audio: 0, 已在私有目录: 8116, 保留冲突: 0, 两处都无: 0`。

### 3. README 的音频通道与实现不符（文档漂移）

- README 原文：「发音: 游戏在 `vocabulary/<word>.mp3` 直接命中本地法语发音」，
  且流水线图里也写 `gen_word_audio.py → vocabulary/<word>.mp3`。
  实际是 `fr_word_audio/<word>.mp3` + 插件拦截 `VocabularyAudioPlayer.PlayWordAudio`。
- 这不只是笔误：它是**与 IMPLEMENTATION.md §1.5 的有意分歧**，但文档里没记这个分歧，
  照 README 或照契约字面复刻都会做出错的实现。
- **修复**：README 新增「与 IMPLEMENTATION.md 的有意分歧」一节，写明分歧点
  （8,116 词中 1,638 个与英语原库同形 → 共享 `vocabulary/` 会让英/日语词书听到法语）、
  实际目录、读取路径、涉及脚本；并在维护注意里补「改源码必须重跑 build.cmd」。

### 4. `es3_safe.require_game_closed()` 健壮性（本地可用但脆弱）

- 原实现 `subprocess.run(['tasklist', ...], check=True)`：
  `tasklist` 不在 PATH 时抛裸 `FileNotFoundError`（而非函数自己设计的「无法确认」错误）；
  且 `check=True` + 事后判断 returncode，语义重复。
- **本机实测**：`tasklist /FI ... /FO CSV /NH` 无匹配时把中文提示写到 **stdout**
  （stderr 为空），因此现有判定在本机恰好成立 —— 我**没有**验证英文 Windows 的行为，
  不声称它在其它语言环境下会失败。
- **修复**：定位 `tasklist` 时带 `%SystemRoot%\System32` 兜底；`OSError`/非零返回码
  统一转成同一条可读错误；只认「字段数 ≥2 且首列为 `wcp.exe`」的 CSV 行。

### 6. `BookProfiles.cs` 三副本漂移隐患（致命级失败模式）

- `mod_fr_wordlist/BookProfiles.cs` 与 `mod_book_name/BookProfiles.cs` 此前仅注释不同。
  它的危险之处：`mod_fr_wordlist/build.cmd` 编译的是 `mod_book_name/BookProfiles.cs`，
  而 `tools/test_runtime_scope_fr.py` 编译的是 `mod_fr_wordlist/BookProfiles.cs`
  —— 即**测试验的是副本、发货用的是正本**。一旦有人改错副本，词书指纹就会漂移，
  而指纹不一致 = 插件永远认不出自己的词书（全功能静默失效）。
- **修复**：三份强制逐字节一致（同步为同一内容）+ 上述第 5 条的新增校验项长期看住。

## 三、复查确认无误的部分（无需改动）

- **词书身份三重校验是 Fail-Closed 的**：`BookStateRaw()` 要求存档已读档
  (`BookReady`) + 内存书名解析出槽位 + 内存词表 Profile 为法语 + 存档槽位 Profile 与内存 Profile 同 Id；
  任一不满足即返回 0，插件全线不动作。与 §4.1.3「读档完成前不得干预」一致。
- **例句音频契约端到端验证通过**：模拟插件的 `ExtractFr` 剥离逻辑对全部
  **24,348 句**比对 —— 0 句被拒、0 句文本漂移、0 句 md5 落空。全角括号/换行等
  会破坏切分的字符在法语原文中不存在（`gen_pipeline_fr.py` 已禁止中文译文含括号，
  正好保护了这条契约）。
- **保留设备名处理正确**：`aux`/`con`/`nul` 三个法语词音频均由 `\\?\` 扩展路径正常落地，
  共享目录零残留。
- **ES3 写入路径安全**：`es3_safe.write_values` 采用文本切片保型改写（不重新序列化）、
  拒绝重复键、写前二次比对文件未被改动、原子替换、保 BOM —— 符合 §1.1「绝对禁止用简单 JSON 库直接回写」。
- **灌库幂等 + 同形词保护**：`patch_local_db_fr.py` 以 `word` 为主键 DELETE→INSERT，
  并跳过 1,638 个英法同形词（英文释义/例句保持原版，运行时按词书双向切换），
  与 §4.4.1「基于 word + 原文的复合主键定位」方向一致。
- **共享库稳态自检**：`verify_all_fr.py` 用英文基线库逐词比对同形词
  pron(1638/1638) 与 sentence2，确认共享库停在英文态。
- 三个测试（`test_runtime_scope_fr` / `test_runtime_ui_fr` / `test_daily_state_fr`）全过；
  `gen_pipeline_fr.py summary` = 8116/8116 达标，0 剩余批次。

## 六、第三轮复查（2026-09-14，当前轮）

本轮针对日语复刻文档的「严格隔离、可恢复、可复现」要求，补齐了以下实际缺口：

1. **每日队列不再只修复空队列**：`RepairDailyQueue` 现在逐项校验

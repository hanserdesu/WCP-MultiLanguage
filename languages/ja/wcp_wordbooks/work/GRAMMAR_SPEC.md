# 语法讲解内容生产契约 (子代理照做)

目标: 为「语法路线词书」写每个语法占位词的 3 条例句栏讲解。
游戏显示格式: `例句：日本語。（中文讲解）` —— 日文部分会被 TTS 朗读,
中文部分是给学习者看的讲解, 所以 **ja 必须是自然日语, 讲解全放 zh**。

## 输入

`wcp_wordbooks/work/gchunk_NN.json`:
```json
{"chunk": 0, "points": [{"gid":"G001","stage":1,"name":"て形","kana":"てけい","brief":"先后・并列・手段・原因"}, ...]}
```

## 输出

写到 `wcp_wordbooks/work/grammar_out_NN.json` (ensure_ascii=False, UTF-8):
```json
{"G001": [["动词的て形例句。", "接续：……"], ["…。", "用法：……"], ["…。", "注意：……"]], ...}
```
- key = gid, value = 恰好 3 行 `[ja, zh]`
- 只写分配给你的 gid, 不许多写

## 三行的分工 (zh 首词必须是规定前缀)

| 行 | ja 放什么 | zh 必须以…开头 |
|----|-----------|----------------|
| 1 | 最小接续示例句: 一句能看清「接续形状」的短句 | `接续：` 接续公式(用中文描述, 如: 动词て形＋后句)＋本句中文翻译 |
| 2 | 主用法情景例句 | `用法：` 核心用法说明＋本句中文翻译 |
| 3 | 另一场景/语体的例句 | `注意：` 易错点/近义辨析/活用提醒＋本句中文翻译 |

zh 里引用日文术语（如「て形」「ます」「ない」）可自由出现，但 zh 必须
以中文讲解为主体，不得写整句日文（校验器会抓连续 6 假名以上的日文串）。
zh 总长 ≤ 60 字；zh 里绝不允许出现 ASCII 字母或数字。
翻译写法: `接续：动词て形＋后句，表先后。本句：早上起床后喝咖啡。`

## 硬性规则 (脚本逐条查, 违反即 FAIL)

1. 每点恰好 3 行; 3 句 ja 互不相同 (不同场景/搭配/语体)
2. ja 6~70 字, 以 `。` `！` `？` 结尾
3. ja 每个字符必须在 JMDict 日语用字白名单内 —— **绝不写简体中文专用字**
   (选→選、说→話/説、记→記、写→書、现→現、语→語、单→単、读→読)
4. ja 不含 ASCII 字母/数字、不含 `~` `〜` `【】`; 不要在 ja 里写公式,
   公式全放 zh
5. zh 1~60 字, 无 ASCII 字母/数字; 假名只许出现在「」内
6. JSON 合法 UTF-8, ensure_ascii=False

## 质量红线 (脚本查不到, 但必须守)

- ja 是**真实可朗读的句子**, 不是模板填空; 活用词要用**能看出接续形状**的原形
  或明确接续 (て形课就写 `〜て、〜` 实句)
- 例句词汇难度贴合该语法点的 JLPT 级别 (N5 点就用 N5 词汇)
- 3 句覆盖不同用法面: 比如「は」的 3 句分别体现 主题对比/新旧信息/否定范围
- 「注意」栏写真正易错的东西 (接续限制、自动词他动、近义差、语体)
- 不写整词英文; 长度自然, 不写翻译腔

## 报告格式 (一句话)

```
NN PASS（G001-G008 共8点）/ ...   或如实说明卡在哪条规则
```

**不许谎报 PASS。**
